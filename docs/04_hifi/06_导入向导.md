# 06 · 导入向导

> **本屏为 [TBD-FE] 功能缺口的设计基线：本轮高保真开发不实现，仅供未来开发引用。** 后端能力已全部就绪（`POST /files` 源文件上传、`POST /import` 三格式清单导入、批次报告、按批次回滚），仅缺前端入口（dev 文档 §9.2 明确列为前端覆盖缺口）。本文只定视觉与布局规格，不含实现排期。
>
> 定位：工作台的「数据入库」入口。把三步导入（① 上传源文件 → ② 上传清单 → ③ 校验入库，后端文档 §六）呈现为一个 **xl 模态向导**，四步条驱动：**上传源文件 → 上传清单/选格式 → 校验与执行 → 批次报告**。与 01–05 相比本页是唯一的纯新增屏，全部控件复用 00 §7 通用规格，仅登记少量新形态（文末「待补充 token」）。
>

## 三、逐区域视觉规格

### 3.1 模态骨架与头部（h-12）

- 遮罩：`fixed inset-0 z-50 bg-slate-900/40 animate-fade-in`（上传/提交 busy 中点击不关，§一）；面板 `relative z-[51] mx-auto flex max-h-[85vh] w-full max-w-[880px] flex-col overflow-hidden rounded-xl border border-line bg-card shadow-modal animate-modal-in`，`role="dialog" aria-modal="true" aria-labelledby`。
- 头部（00 §7.6）：左：图标块 `flex h-8 w-8 shrink-0 items-center justify-center rounded-lg border border-blue-200 bg-blue-50 text-blue-700`（upload 图标 16px，缺口见待补充 #4）+ 标题 `text-[14px] font-semibold text-ink`「导入数据」+ 右侧版本预分配徽章（步骤③起显示）`rounded-full border border-line bg-subtle px-2 py-px font-mono text-[11px] text-ink-muted`「将入库为版本 v{n+1}」（n 为当前最大版本号；报告页替换为实际值）。右：关闭 ghost 图标按钮（规格同 05 §3.1：`flex h-8 w-8 items-center justify-center rounded-lg text-ink-faint transition-colors duration-150 hover:bg-subtle hover:text-ink-soft` + 统一 ring）。
- 头部说明「三步入库：源文件 → 清单 → 校验报告」放步骤②前的步骤身首条说明卡，不占头部（与 04/05 头部单行约定一致）。

### 3.2 步骤条（Stepper）

```html

  <!-- 每步：节点 + 标签；节点间连接线 h-px flex-1 -->

    </li>
    <span class="h-px flex-1 {已走过 bg-blue-300 | 未走 bg-line}" aria-hidden="true" />
    <!-- …步骤 2/3/4 同构；已完成步骤节点内容换 check 图标 12px -->
  </ol>
</nav>
```

节点四态（编号在节点内，已完成换 check 12px；连接线两态 `bg-blue-300` / `bg-line`，00 §2.1 blue-300 画布装饰线档）：

| 态 | 节点类 | 标签类 |
|---|---|---|
| 已完成 | `bg-success-soft text-success-deep`（00 §2.3 成功语义） | `text-[12px] text-ink-soft` |
| 当前 | `bg-blue-600 text-white font-semibold`（当前项语义，00 §2.1） | `text-[12px] font-medium text-ink` |
| 未到达 | `border border-line bg-card text-ink-faint` | `text-[12px] text-ink-faint` |
| 错误回跳后的已完成 | 同已完成（错误在步骤身内呈现，步骤条不染红——报告的拒绝属正常业务结果，非流程失败） | 同已完成 |

步骤条为纯展示（`aria-current="step"` 标当前步），不做点击跳转；回退只经脚部「上一步」。规格缺口登记见文末待补充 #1。

### 3.3 步骤① · 上传源文件

**说明卡（步骤身首条）**：`flex items-start gap-2 rounded-lg border border-line bg-card px-3 py-2.5 text-[12px] leading-5 text-ink-muted`（info 图标 12px `text-ink-faint`）「第一步：上传第一手源文件。导入清单将以文件 ID 或原始文件名引用它们；相同内容（sha256）自动去重复用。」

**Dropzone（主上传区，见文末待补充 #2）**：

```html
<label class="group flex cursor-pointer flex-col items-center justify-center gap-2
             rounded-xl border-2 border-dashed border-line-strong bg-page px-6 py-10 text-center
             transition-colors duration-150 hover:border-blue-300 hover:bg-blue-50/40
             focus-within:ring-2 focus-within:ring-blue-600/60">
  <Icon name="file" size={24} className="text-ink-faint group-hover:text-blue-600" />
  <span class="text-[13px] font-medium text-ink-soft">拖放源文件到此处，或点击选择</span>
  <span class="font-mono text-[11px] text-ink-faint">csv / xlsx / json · 单文件 ≤ 50MB（MAX_UPLOAD_MB）· 按 sha256 去重</span>
  <input type="file" multiple accept=".csv,.xlsx,.json" class="sr-only" />
</label>
<!-- 拖拽悬停（drag-over）：border-blue-400 bg-blue-50/60；禁用（上传中）：opacity-50 cursor-not-allowed -->
```

（`border-2 border-dashed` 为拖放命中的功能性边框非装饰（00 §4.3 禁的是装饰性粗边框）；如需严格执行该条可降为 `border` + `bg-subtle`，登记在待补充 #2 由 00 裁决。多选 `multiple`；上传由前端逐文件调 `POST /files` 或整批一次提交以 API 文档 §3.1 `files[]` 为准——本文只定视觉，不冻结实现 `[TBD-FE]`。）

**已上传文件列表**（容器 `divide-y divide-line-soft overflow-hidden rounded-xl border border-line bg-card`，行 `flex items-center gap-2.5 px-3 py-2.5`）：

| 元素 | 规格 |
|---|---|
| 文件图标 | file 14px `shrink-0 text-ink-faint` |
| 文件名 | `min-w-0 flex-1 truncate font-mono text-[13px] text-ink`（`title` 全名） |
| 大小 | `shrink-0 font-mono text-[11px] tabular-nums text-ink-faint`（如 12.4MB） |
| 类型 chip | `rounded border border-line bg-page px-1.5 py-px font-mono text-[11px] uppercase text-ink-faint`（csv/xlsx/json；与 05 §3.1 格式 chip 同规格） |
| 去重徽章 | 复用：`rounded-full border border-transparent bg-info-soft px-1.5 py-px font-mono text-[11px] text-info-deep`「复用已有 #id」（`deduped: true`）；新登记：`border-line bg-subtle text-ink-muted`「新登记 #id」（00 §7.4 状态徽章 + 05 待补充 #2 中性档） |
| 移除按钮 | 图标按钮 `h-6 w-6 rounded-md text-ink-faint hover:text-danger-deep hover:bg-danger-soft`（close 12px，`aria-label="移除文件 {name}"`；仅前端放弃引用，已登记记录由 sha256 去重兜底） |

| 单文件失败行 | 整行 `bg-danger-soft`，原因 `text-[12px] leading-4 text-danger-deep`（后端 400/413 detail；任一文件出错整批失败，列表保留已成功项 + 顶部 danger 汇总条，见 §五） |

**空态**（无文件且非上传中）：Dropzone 本身即空态（图标 + 文案），不另设 00 §7.9 空态块；脚部「下一步」disabled（`至少上传一个文件` 才可前进，API §3.1 400 语义前置）。

**格式选择**（`fieldset` + `legend` sr-only「清单格式」；三张 radio 卡横排 `grid gap-3 sm:grid-cols-3`）：

### 3.5 步骤③ · 校验与执行

**提交摘要卡**（`rounded-xl border border-line bg-card`，行 `flex flex-wrap items-center justify-between gap-x-3 gap-y-1 px-3 py-2.5` + `divide-y divide-line-soft`）：

| 行 | label（`text-[12px] text-ink-muted`） | 值 |
|---|---|---|
| 清单格式 | 左 | `font-mono text-[13px] font-medium text-ink`（csv/xlsx/json） |
| 绑定源文件 | 左 | chips（§3.4 规格），`font-mono text-[11px] tabular-nums text-ink-faint` 计数「N 个」 |
| 清单文件 | 左 | `truncate font-mono text-[13px] text-ink`（csv 为两文件名「、」连接，`title` 全量） |

摘要卡下方 info 条（00 §2.3 info 组）：`flex items-start gap-2 rounded-lg border border-blue-100 bg-blue-50 px-3 py-2.5 text-[12px] leading-5 text-blue-800`（info 12px `text-blue-700`）「提交后后端在同一事务内完成行级校验与入库：行级失败进报告、不阻塞成功行；清单文件级错误（缺 sheet、表头缺失、根解析失败等）整批失败。」

**执行态**（点击脚部「开始校验并导入」后，步骤身整体替换）：

```html
<div class="flex flex-col items-center justify-center gap-3 py-16" role="status" aria-live="polite">
  <span class="h-6 w-6 animate-spin rounded-full border-2 border-blue-200 border-t-blue-600" aria-hidden="true" />
  <p class="text-[13px] font-medium text-ink-soft">正在校验并导入…</p>
  <p class="text-xs text-ink-muted">清单较大时可能需要数十秒，请勿关闭窗口</p>
</div>
```

（后端 `POST /import` 一次性返回、无流式进度接口，执行态只有不确定 spinner + 文案 `[ASSUMPTION]`；脚部主操作 disabled busy。）

**文件级错误态**（400/404/413/422）：danger 卡 `rounded-xl border border-danger/25 bg-danger-soft px-3.5 py-3`（00 §2.3；`role="alert"`）——标题 `text-[13px] font-medium text-danger-deep`「导入未执行」+ 后端 detail 原文 `mt-1 text-[12px] leading-5 text-danger-deep` + 动作「返回上一步」secondary `h-8 px-3 text-[12px]`（refresh 12px「重试上传」不必需——错误多为清单问题，回步骤②修改后重新提交）。

> **低保真 → 后端能力映射说明**：低保真「校验报告（预检）→ 确认入库为版本 v3」两段式在后端无对应接口——`POST /import` 校验与入库同事务完成，拒绝行不阻塞成功行（后端文档 §六.4）。本设计据此把步骤③定为「校验与执行」（提交即执行），低保真的「确认入库为版本 v3」按钮**不保留**，其「将入库为版本 v3」徽章保留为头部版本预分配提示（§3.1），实际版本号在步骤④ 报告页呈现。若未来需要真两段式（预检 dry-run 后再入库），需后端新增接口 `[TBD-BE]`。

### 3.6 步骤④ · 批次报告（完成态）

**成功条**：`flex flex-wrap items-center gap-x-2 gap-y-1 rounded-lg border border-success/25 bg-success-soft px-3 py-2.5 text-[13px] leading-5 text-success-deep`（check 12px）——「导入完成 · 已入库为版本 v{version_no} · 批次 #{batch_id}」（`font-mono tabular-nums`）。

## 八、无障碍要点（本页特有）

1. **文件选择的键盘路径**：Dropzone 以 `label` 包裹 `sr-only` input，键盘 Tab 到 label 即可 Enter 触发选择器；`focus-within` ring 可见（00 §10.3）。
2. **步骤语义**：步骤条 `aria-label="导入步骤"`，当前步 `aria-current="step"`；步骤名即信息，进度不只靠颜色（已完成节点有 check 图标）。
3. **上传与执行的可感知**：文件上传行、执行态面板均 `role="status"`（执行态另加 `aria-live="polite"`）；错误条 `role="alert"`。
4. **busy 锁定**：上传中/提交中 Esc、遮罩、关闭、脚部按钮全部禁用（同 ConfirmDialog busy 规则）；关闭前有已上传文件时经 ConfirmDialog 二次确认（文字说明，不只靠弹窗本身）。
5. **表单标签**：格式选择用 `fieldset` + `legend`（sr-only）+ `label` 包裹 radio；清单上传位各有可见 label 文本（「datasets.csv…」）。
6. **报告可读性**：拒绝行以语义列表（`role="list"`）呈现，行号 mono `tabular-nums` 对齐；拒绝原因全文可达（非截断 title）。
7. **色彩不做唯一编码**：ok/merged/rejected = 三组语义色 + 文字标签（成功/合并/拒绝）；统计卡数字色只是冗余，标签文字承载语义。
8. **对比度抽查点**：`blue-800` on `blue-50`（8.01）、`danger-deep` on `danger-soft`（5.91）、`warning-deep` on `card` 白底（约 5.9，档同 §2.6 warning-deep on white 族）、`success-deep` on `card`（6.81 族）——组合均在 00 §2.6 表内或同档推算；`ink-soft` 报告正文 on card 10.36。
