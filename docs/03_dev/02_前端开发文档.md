## 一、技术栈与依赖

前端为 React 19 单页应用（SPA），Vite 开发与构建，TypeScript 严格模式，Tailwind CSS 原子样式，`@xyflow/react` 画布，`@dagrejs/dagre` 分层布局。包管理使用 **npm**（存在 `package-lock.json`，禁止 pnpm / yarn）。

**刻意不引入**（以代码为准）：

- **无 UI 组件库**：根 README 技术栈小节明确「组件源码内置，无额外 UI 组件库」——按钮、输入框（`.field-input`，`src/index.css`）、弹窗、抽屉、Toast 等全部由项目内组件与 Tailwind 类实现；
- **无状态管理库**：设计方案 §五曾提「zustand 做画布状态」，实现未采用（React 内置 `useState`/`useRef`，见 §四；差异记录在 §九）；
- **无路由库**：无 react-router，`App.tsx` 按「是否有会话」在 `LoginPage` 与 `Workspace` 两个屏之间条件渲染；
- **无 HTTP 库**：只用 `fetch`（README 明确「前端只使用 `fetch` 访问 API」）；
- **无图标库**：`components/Icon.tsx` 内置 42 个内联 SVG 图标（`IconName` 联合类型）。

TypeScript 配置要点（`tsconfig.json`）：`target: ES2022`、`moduleResolution: "bundler"`、`verbatimModuleSyntax`、`strict` + `noUnusedLocals` + `noUnusedParameters` + `noFallthroughCasesInSwitch` + `erasableSyntaxOnly`、`jsx: "react-jsx"`、`types: ["vite/client", "node"]`、`include: ["src", "vite.config.ts"]`。

Tailwind 主题要点（`tailwind.config.cjs`，content 覆盖 `index.html` 与 `src/**/*.{ts,tsx}`）：

- 自定义色板：`canvas`/`surface`（米色纸面）、`ink`（墨绿文字，4 档）、`line`（分隔线，3 档）、`pine`（主色，50–900）、`ember`/`ochre`/`rosewood`（强调色）、`ai`（AI 专属蓝 `#2f64d8` 系）；
- 字体：`sans`（Noto Sans SC 等）、`display`（Newsreader/宋体系）、`mono`（IBM Plex Mono 等，经 `index.css` 的 Google Fonts `@import` 加载）；
- 阴影 `card`/`float`/`node`/`node-active`、背景 `fine-grid`（28px 网格）、动画 `fade-up`/`fade-in`/`modal-in`/`soft-pulse`。

## 三、开发工作流

### 3.1 命令

```bash
cd prototype/frontend
npm install        # 安装依赖（npm，生成/使用 package-lock.json）
npm run dev        # vite 开发服务器 → http://localhost:5173
npm run build      # tsc -b && vite build（先类型检查再构建，产物 dist/）
npm run preview    # vite preview（本地预览构建产物）
npm run typecheck  # tsc -b（仅类型检查，README 未列出，见 package.json scripts）
```

### 3.2 Vite proxy 与后端依赖

`vite.config.ts` 将以下 **12 个前缀**全部转发到 `http://127.0.0.1:8000`（`changeOrigin: true`）：

`/auth`、`/datasets`、`/lineage`、`/fields`、`/edges`、`/annotations`、`/changes`、`/version-tags`、`/users`、`/ai`、`/files`、`/import`

即开发态下前端与后端同源（相对路径请求），无跨域配置。`lib/api.ts` 的 API 基址取 `import.meta.env.VITE_API_BASE_URL`（默认空字符串 = 同源相对路径；可用于构建态指向独立部署的后端）。

**对后端启动的依赖**：所有数据（登录、数据集、子图、预览、AI）都来自后端，开发前必须先启动后端（见根 README 后端小节：仓库根 `cp .env.example .env` → `cd prototype/backend && uv sync && uv run uvicorn lineagelite.main:app --reload`）。后端未启动时前端不会白屏：登录页显示「无法连接服务，请稍后重试」，进入工作台后数据集列表显示错误卡与「重试」按钮（提示「请检查后端服务是否已启动」）。需要演示数据可执行后端 `uv run python -m lineagelite.seed_demo`。

## 四、认证与全局状态管理

### 4.1 登录流程与 JWT 存储

1. `App.tsx` 初始化时 `loadSession()` 从 `localStorage` 读会话（键 `clew.session`，JSON：`access_token`/`token_type`/`username`/`role`；结构不合法或损坏即丢弃返回 null）；
2. 无会话 → 渲染 `LoginPage`：提交表单调 `login(username, password)`（`POST /auth/login`），成功后 `persistSession(session)` 写入 `localStorage` 并回调 `App`；失败（含 401 密码错误）仅在登录页内联显示错误，**不**触发过期事件（该请求不带 token）；
3. 有会话 → 渲染 `Workspace`，并以 `key={session.access_token}` 挂载——切换账号/重新登录会强制整树重建，不残留旧会话的页面状态；
4. 后续所有需鉴权请求由 `lib/api.ts` 统一附加 `Authorization: Bearer <access_token>`（`token_type` 字段仅存储展示用，请求头固定用 `Bearer`）；
5. 登出：`TopBar` 用户菜单「退出登录」→ `clearSession()`（删除 `localStorage` 键）→ 回登录页。

### 4.2 401 全局处理

`lib/api.ts` 的 `request()`（及 `downloadSourceFile`）在响应为 401 **且本次请求携带了 token** 时，向 `window` 派发自定义事件 `clew:auth-expired`（常量 `AUTH_EXPIRED_EVENT`）；`App.tsx` 监听该事件，执行 `clearSession()` + 置空会话 + 在登录页顶部提示「登录已过期，请重新登录后继续。」。即 README 所述「任意已认证请求返回 401 时会回到登录页」。

### 4.3 全局状态清单与存放方式

前端**没有**状态管理库，也没有 React Context：会话是唯一跨刷新持久的状态，其余全部为组件内 React state、经 props 单向下发。

| 状态 | 存放位置 | 说明 |
|---|---|---|
| 登录会话（token/用户名/角色） | `App` `useState` + `localStorage['clew.session']` | 刷新页面后恢复；`loadSession` 校验字段完整性 |
| 401 过期提示文案 | `App` `useState`（`notice`） | 回登录页时展示 |
| 数据集列表 / 加载错误 / 重载 key | `Workspace` | `GET /datasets`，AbortController 可取消 |
| 搜索词、选中数据集（种子）、跳数（默认 3，可选 1–5） | `Workspace` + `TopBar`/`DatasetSidebar` 受控 | 种子或跳数变化即重新拉子图 |
| 当前子图 `graph` 与 AI 子图 `aiGraph` | `Workspace` | `displayGraph = aiGraph ?? graph`；AI 出图优先，数据集/跳数/刷新变化时清空 `aiGraph` |
| 画布过滤（`minConfidence`/`hideAiEdges`/`confirmedOnly`） | `Workspace`，控件在 `DatasetSidebar` | 只过滤展示，不改后端数据 |
| 节点折叠集 `collapsedIds` / 字段展开集 `fieldsExpandedIds` | `Workspace` → `LineageCanvas` props | 不持久化，换种子即重置 |
| 折叠分组 `groups`、选中节点、拖拽位置缓存 | `LineageCanvas` 内部 state/`useRef` | 仅画布内生命周期 |
| 选中字段 / 选中边 / 回源预览目标 / 新边草稿 / 待删边 | `Workspace` | 驱动右侧面板与弹窗 |
| 抽屉与弹窗开关（版本/用户/AI） | `Workspace` | 条件渲染 |
| Toast 消息 | `Workspace`（4.2s 自动消失） | 全局操作反馈 |

## 五、API 访问层（lib/api.ts 与 types.ts）

### 5.1 请求封装与错误约定

- `request<T>(path, init, token?)` 是唯一的 JSON 请求入口：有 `body` 且未设置时自动加 `Content-Type: application/json`；有 token 时加 Bearer 头；`!response.ok` 时抛 `ApiError(status, message)`；`204` 返回 `undefined`。
- 错误消息解析（`readErrorDetail`）：优先取后端 `detail` 字符串；FastAPI 校验错误（`detail` 为数组）时拼接各项 `msg`（「；」分隔）；无可用 detail 时按状态码兜底：401「登录已过期」、403「当前账号无权执行此操作」、404、409「操作冲突」、422「请求参数不合法」、其余「请求失败（HTTP n）」。非 JSON 错误体（如 HTML 错误页）不透传原文，避免直接展示给用户。
- 所有请求函数接受可选 `AbortSignal`，组件在卸载或发起新请求时 `abort()`；`isAbortError()` 用于统一静默处理取消。
- `downloadSourceFile(token, fileId, filename)` 独立于 `request`（需要 blob）：fetch → `URL.createObjectURL` → 隐藏 `<a download>` 点击 → `revokeObjectURL`；存储路径不经前端，只接受源文件 ID（见 `lib/api.ts` 尾注）。

### 5.2 types.ts 与后端契约的对应

`src/types.ts` 是前端唯一类型出口，与后端 REST 契约一一对应（字段级定义见 [./05_API接口文档.md](./05_API接口文档.md)，此处只列分组）：

| 类型组 | 类型 | 对应后端 |
|---|---|---|
| 认证 | `Session` / `LoginResponse` | `POST /auth/login` 响应 |
| 数据集 | `DatasetSummary`（含 `field_names`） | `GET /datasets` |
| 子图（GraphPayload） | `LineageGraph` = `LineageDataset[]` + `LineageEdge[]`；`DatasetField` 内嵌 `LocatorEnvelope{type, input, resolved}` 与 `SourceFileRef` | `GET /lineage/subgraph`；设计方案 §5.2 的统一渲染协议，前端只有一个消费入口（`Workspace.applyGraph`） |
| 边 | `LineageEdge`（`id` 为数据库主键，人工编辑/删除用它定位；`from_field`/`to_field` 为 null 表示表级边）；`EdgeDraft`/`EdgeCreatePayload`/`EdgePatchPayload` | `POST /edges`、`PATCH/DELETE /edges/{id}` |
| 字段 | `FieldPatchPayload`（description/field_type/src_locator） | `PATCH /fields/{dataset_id}/{field_name}` |
| 回源预览 | `PreviewResponse` = `PreviewFileRef` + `PreviewVerification` + `LocatorEnvelope` + (`CsvPreview` \| `XlsxPreview` \| `JsonPreview`) | `GET /fields/{dataset_id}/{field_name}/preview` |
| 标注 | `Annotation`、`AnnotationCreatePayload`、`TargetKind`（dataset/field/edge） | `GET/POST /annotations` |
| 变更历史 | `ChangeEntry`、`ChangeOp` | `GET /changes` |
| 版本 | `VersionTag`、`VersionTagDiff(Item)`、`ImportBatch` | `GET/POST /version-tags`、`/version-tags/diff`、`/version-tags/{name}/rollback`、`GET /import/batches` |
| 用户 | `UserAccount` | `GET/POST /users`（admin） |
| AI | `AiStatus`、`AiChatMessage`、`AiFocus`、`AiToolTrace`、`AiChatResponse{answer, tool_trace, graph?}`、`AiSuggestion`、`AiEdgeKey` | `/ai/status`、`/ai/chat`、`/ai/suggest`、`/ai/suggest/confirm`、`/ai/suggest/reject` |

前端专有（非后端契约）：`FieldSelection`（画布选中的 dataset+field 组合）。

## 七、血缘画布实现

对应设计方案 §五（可视化界面）。核心链路：`Workspace` 持有 `LineageGraph` → `LineageCanvas` 转换为 ReactFlow 节点/边 → 自定义组件渲染。

### 7.1 自定义节点与边

- `nodeTypes = { dataset: DatasetNode, group: GroupNode }`、`edgeTypes = { lineage: LineageEdgeView }`（`LineageCanvas.tsx` 顶部注册）。
- **DatasetNode**：固定宽 288px 的卡片；表头左/右各一个**表级** handle（`table:in` / `table:out`，位于标题行高度）；每个字段行左/右各一个**字段级** handle（`field:in:<name>` / `field:out:<name>`，id 由 `lib/handles.ts` 生成）。`isConnectable={connectable}`——viewer 的 handle 不可拖线（`nodesConnectable={canEdit}` 同时关闭画布连接）。种子节点用 pine 高亮与「种子」徽章，`zIndex` 抬升。
- **GroupNode**：仅表级 handle 且 `isConnectable={false}`，跨组聚合边指向它。
- **LineageEdgeView**：`getSmoothStepPath`（borderRadius 18 / offset 30）+ `MarkerType.ArrowClosed` 箭头；18px 宽透明命中路径保证细线可 hover；tooltip 用 `EdgeLabelRenderer` 渲染在 ReactFlow 之外（`nodrag nopan`）。视觉规则 `getEdgeVisual(edge)`（色值与 `lib/edgeColors.ts` 单一来源一致；下表已同步 hi-fi 迁移后的现值）：

| 来源/形态 | 颜色 | 线型 | 宽度 | 其他 |
|---|---|---|---|---|
| `source='ai'` | `#4F46E5`（`EDGE_COLORS.ai`） | 虚线 `6 5` | 1.8 | `animated`（流动动画） |
| `source='manual'` | `#D97706`（`EDGE_COLORS.manual`） | 字段级实线；表级虚线 `4 5` | 1.7 | — |
| imported 字段级 | `#475569`（`EDGE_COLORS.imported`） | 实线 | 1.55 | — |
| imported 表级 | `#64748B`（`EDGE_COLORS.importedWeak`） | 虚线 `4 5` | 1.4 | — |
| 同名字段匹配（derived，视图派生） | `#94A3B8`（`EDGE_COLORS.derived`） | 点状虚线 `2 4` | 1.3 | 不可选中/编辑，tooltip 只读 |
| 追踪链路命中（focusState='chain'） | `#DC2626`（`EDGE_COLORS.focus`） | 沿用原形态线型 | 2.6 | `animated`；`zIndex: 2`；其余边压暗 opacity 0.15 |

### 7.2 dagre 分层布局（lib/layout.ts）

- 图参数：`rankdir: 'LR'`（上游在左、下游在右，设计方案 §5.1）、`align: 'UL'`、`nodesep: 42`、`ranksep: 124`、`marginx/y: 36`、`acyclicer: 'greedy'`（自环/回边处理）、`ranker: 'network-simplex'`，`multigraph: true`（同对节点多条边）。
- 自环边（`from_dataset === to_dataset`）与两端不在子图内的边不参与布局；布局只定**数据集节点**位置（组节点取成员包围盒中心，见 7.4）。
- 节点高度按内容估算（`estimateNodeHeight`）：常量 `NODE_HEADER_HEIGHT=56`、`FIELD_ROW_HEIGHT=34`、`FIELD_PREVIEW_LIMIT=5`（节点内字段默认只展示前 5 个）、折叠态 `COLLAPSED_BODY_HEIGHT=48`、空字段 42、展开/收起切换行 26。
- **拖拽位置记忆**：`LineageCanvas` 用 `draggedPositions` ref 记录用户手动拖过的节点；重建节点时优先复用，未被拖过的节点跟随 dagre 新布局。种子或跳数变化视为新图——清空拖拽缓存与分组后整体重排。

### 7.3 字段级/表级连线与 handle 约定

- 边构建规则（`LineageCanvas` 副作用）：`from_field`/`to_field` 任一为 null → 表级边，走 `table:out → table:in`；两端都是字段 → 字段级边，走 `field:out:<f> → field:in:<f>`。
- **折叠联动**：任一端节点处于收起态（`collapsedIds`）→ 字段级边隐藏（只留表级边）；字段部分折叠时（默认前 5 个），任一端字段不在可见集合 → 该边同步隐藏。
- **同名字段匹配推断线（derived，视图派生、不落库）**：`lib/fieldChain.ts` 的 `deriveFieldMatches` 对每条**表级边**（`from_field`/`to_field` 任一为 null）推导——两端数据集共有、且未被这对数据集之间任何一条显式字段级边占用为端点的字段名，生成 `A.f → B.f` 推断线（方向跟随表级边）。显式字段级边只代表单字段映射，不参与推导，避免与人工/AI 确认的映射矛盾。推断线不可选中/编辑（`selectable: false`、无操作按钮），tooltip 标注「同名字段匹配 · 推断」；折叠/可见性联动与字段级边一致，任一端处于折叠组时由跨组聚合边表达、不单独渲染。推导基于画布实际收到的边集合（置信度/AI 过滤同时减少推导线）。
- **字段追踪链路（`focusedField` 焦点态）**：点击字段行 → `computeFieldChain` 以该字段为起点，沿「库内字段级边 + 推断线」做无向 BFS 收集整条上下游链（传递到链路尽头，不只一跳）：命中边（`focusState='chain'`）stroke 换 `#DC2626`、宽 2.6、`animated`、`zIndex: 2`；其余连线（含表级边与聚合边）压暗至 opacity 0.15，箭头 marker 走 `withAlpha(color, 0.3)` 降 alpha。命中字段行同步高亮：聚焦行 `bg-red-50` + 红圈 + 红点、链路行 `bg-red-50/70`，字段级 handle 转 `.field-handle-traced` 红色。清除时机：点画布空白（`onPaneClick`）、点连线（打开边详情）、框选节点（折叠组流程）、切换种子/跳数、子图刷新后焦点字段不存在。追踪前自动保证链路可见：收起的节点自动展开（`onToggleCollapse`）、超出前 5 个的字段列表自动展开（`onToggleFields`）；字段没有任何字段级关联时不高亮、不压暗。
- **拖 handle 新增血缘**（`onConnect`）：校验「字段级与表级不能混连」「同字段/同节点自连拒绝」「handle 前缀解析失败提示重拖」，通过后产出 `EdgeDraft`（字段级/表级由 handle 类型决定）→ `Workspace` 打开 `EdgeCreateModal` 补转换/置信度/备注 → `POST /edges`（人工边 `source='manual'` 由后端落）。
- 框选交互：`selectionKeyCode="Shift"`（框选）、`multiSelectionKeyCode={['Meta','Control','Shift']}`（多选）、`deleteKeyCode={null}`（禁用 Delete 删边，删除必须走详情面板 + 二次确认）。

### 7.4 字段折叠与「框选折叠为组」

- **节点收起**（`collapsedIds`）：表头按钮收起整个字段列表，节点变矮、字段级边隐藏；
- **字段折叠**（`fieldsExpandedIds`）：默认显示前 `FIELD_PREVIEW_LIMIT=5` 个字段，「其余 N 个字段已折叠」一键展开/收起；画布左上角「全部收起/全部展开」批量切换；
- **框选折叠为组**：Shift 框选或多选 ≥2 个数据集节点 → 工具面板出现「折叠选中（N）」；成员节点在**视图层**隐藏（不写后端），替换为 `GroupNode` 占位（置于成员包围盒中心，不参与 dagre）。组内成员之间的边互相抵消；跨组边按「组/数据集对」聚合为一条虚线边（tooltip 显示「跨组聚合 · N 条边」，不可单独操作）。点击组节点或「展开全部组」解散；种子/跳数变化或子图刷新后自动剔除已消失成员、成员不足 2 的组自动解散。此为 M3 前端最小实现取舍（`GroupNode.tsx` 头注释）。

### 7.5 跳数与方向参数

- 跳数：`TopBar` 提供 1–5 档（`HOP_OPTIONS`，注释明确与后端 `/lineage/subgraph` 的 `hops 1..5` 契约一致），`Workspace` 默认 3；变化即重新拉子图并清空 AI 覆盖图。
- 方向：`getSubgraph` 固定传 `direction: 'both'`（上下游双向，画布用 LR 布局区分方向）；后端 `hops` 默认 3、`ge=1, le=5`。

### 7.6 AI 出图联动与统一渲染协议

- 所有子图消费走 `Workspace.applyGraph`（设计方案 §5.2「唯一渲染入口」）：常规子图与 AI 出图共用同一套画布状态清理（保留仍存在的折叠/选中状态、清掉失效选择）。
- `AiAssistantDrawer` 收到响应携带 `graph`（`trace_lineage` 工具最后一次返回的子图）→ `onGraph` → `Workspace.setAiGraph` + `applyGraph` + Toast「画布已更新：N 个数据集 · M 条连线」。AI 子图优先于按种子拉取的子图，直到用户切换数据集/跳数或刷新。
- **AI 高亮联动**（2026-10-24 新增，详见 [06_AI画布联动高亮修复](./06_AI画布联动高亮修复.md)）：响应携带 `highlights`（模型经 `mark_highlight` 工具声明）时，`Workspace` 以 `{seq, fields}` 存入 `aiFieldFocus` 传给画布；`LineageCanvas` 校验字段在子图内存在后，复用 `revealChainFields` 自动展开并把字段应用为追踪焦点（效果同点击字段：链路变红、其余压暗）。每轮回答未声明 `highlights` 时 seq 递增并显式清除上一轮追踪态。
- AI 出图时若原种子不在子图内，用当前聚焦（选中字段/数据集）或子图首节点作为画布种子（`canvasSeedId`）。

### 7.7 source='ai' 边的确认转人工流程

对应设计方案 §6.4 与业务模型不变量「AI 不可直接生效」：

1. **生成**：`DetailPanel`（字段详情）「生成 AI 候选」→ `POST /ai/suggest {dataset, field}` → 后端启发式按同名字段（0.7）/包含关系（0.6）生成候选边并**以 `source='ai'` 落库**；前端随即 `onRefresh` 刷新子图，候选边（蓝虚线 + 流动动画）立即出现在画布；
2. **候选卡处理**：`DetailPanel` 候选卡提供「确认」（`POST /ai/suggest/confirm` → 转为 `source='manual'` 的人工边）与「拒绝」（`POST /ai/suggest/reject` → 删除候选边），处理后从卡片列表移除并刷新画布；
3. **不依赖卡片内存**：画布上任意 `source='ai'` 的边，在 `EdgeDetailPanel` 中都可「确认转为人工边」（同样走 `/ai/suggest/confirm`，以边端点四元组定位）；删除该边则走 `DELETE /edges/{id}`（面板提示「删除等价于拒绝该候选」）；
4. 以上确认/拒绝/生成入口均要求 `canEdit`（editor+），viewer 只读。
5. 过滤兜底：`DatasetSidebar` 的「隐藏 AI 建议边」「仅显示确认血缘」两个开关在展示层剔除 `source='ai'` 边（置信度过滤对无置信度边按 1 处理）。

## 八、角色权限的前端表现

角色体系见业务模型 §二（viewer 只读 / editor 可写业务数据 / admin 管理系统）。`lib/roles.ts` 提供三个纯函数：`isEditor`（editor 或 admin）、`isAdmin`、`roleLabel`（管理员/编辑/只读）。

> **重要边界**：前端的角色控制**只是 UX 层**——隐藏写入口、关闭 handle 连接，让用户少遇到 403。真正的权限校验永远在后端 `require_role` 守卫（每个路由声明最低角色，角色取数据库当前值）。直接调 API 绕过前端 UI 仍会被后端拒绝；详见 [./04_前后端职责边界.md](./04_前后端职责边界.md)（P3 原则）。`lib/roles.ts` 头注释亦明确此点。

各角色的 UI 表现（均为「不渲染写入口」而非置灰）：

| 能力 | viewer | editor | admin | 实现位置 |
|---|---|---|---|---|
| 画布拖 handle 建边 | handle 不可连接（`nodesConnectable=false`、`DatasetNode.connectable=false`） | 可 | 可 | `Workspace` → `LineageCanvas` / `DatasetNode` |
| 边 hover tooltip 的「编辑/删除」按钮 | 隐藏 | 显示 | 显示 | `LineageEdge.tsx`（`canEdit`） |
| 字段编辑（描述/类型/定位器） | 隐藏编辑按钮 | 可 | 可 | `DetailPanel`（`canEdit`） |

## 十、国际化（i18n，2026-10 新增）

### 10.1 方案与结构

自研轻量 i18n，不引入第三方依赖（对齐 00 §7.12 与仓库「禁止未审计依赖」规则）：

```
src/i18n/
├── index.tsx    # I18nProvider + useI18n() → { locale, setLocale, t }；{var} 插值；
│                # localStorage['clew.locale'] 持久化；同步 <html lang> 与 document.title
├── zh.ts / en.ts  # 聚合字典（只做 spread，不写词条）
└── dicts/       # 按命名空间分模块：common.ts（跨组件复用）+ 每组件一个 <ns>.ts
```

- 字典模块写法：`export const zhXxx = { 'ns.key': '中文' } as const;` + `export const enXxx: Record<XxxKey, string> = { ... }`——en 以本地类型约束强制与 zh 键完全一致，漏键在 `tsc` 构建期报错。
- `t(key, params?)`：`{var}` 占位插值；复数语义用措辞规避（如 `'{count} fields'`），不做 ICU 复数规则。
- 任何 React 组件（含文件内子组件）直接调用 `useI18n()`；模块级工具函数（如 `humanizeLocator`、`roleLabel`、HistoryDrawer 的 `valueText`）以 `t` 为参数显式传入。
- 默认 `zh`，不做浏览器语言自动检测；切换即时生效（React state），偏好持久化到 `localStorage['clew.locale']`。

### 10.2 约定与边界

- 词条 key 扁平命名 `命名空间.条目`（`topbar.searchPlaceholder`、`importWiz.title`…）；跨组件复用词条进 `dicts/common.ts`（`common.*`），新增通用词条需确认无同名语义。
- 并行改造约定：每个组件改造只触碰「本组件文件 + 本命名空间字典模块」；`zh.ts`/`en.ts` 聚合注册由基建一次性完成，`common.ts` 禁止并行编辑。
- 不翻译范围（保持原样展示）：后端错误消息（`ApiError.message` 原样透传，后端无错误码契约，EN 模式下后端错误仍为中文——后续项：后端错误码 + 前端映射）、AI 回答内容（后端 SYSTEM_PROMPT 已具备按提问语言回答）、业务数据（数据集/字段名）、技术标识（source 值、csv/xlsx/json、sheet 名）、代码注释。
- 跟随 locale 的工具函数：`formatCount(value, locale)`（`Intl.NumberFormat` zh-CN/en-US）；`<html lang>` 与 `document.title` 由 Provider 的 effect 同步。
