## 一、评审结论摘要

三条主线（证据行号以 2026-10-25 代码为快照，修复后以本轮代码为准）：

1. **AI 模块**：功能闭环完整（SSE 流式、8 工具、双确认流、change_log 全留痕），但对话路径的写类工具（`suggest_lineage` / `draft_descriptions`）**没有角色校验**——viewer 经 `/ai/chat` 触发即可写 edge / `description_draft` 表，直通端点却要求 editor，权限模型被系统性旁路；且上下文无 token 预算、无停止按钮、SSE 无心跳、断开不传播、无速率限制，长跑场景失控。
2. **布局与画布**：xl 断点骨架清晰、三态覆盖好、动画克制；但 TopBar 在 768–1279px 必然横向溢出，血缘边的全部操作依赖 hover 工具条（`edgesFocusable=false`），键盘用户无法触达；画布巨型 effect 每次点字段全量重跑 dagre，大子图可感知卡顿；首屏空态闪现、过滤清空无解释、移动端提示条整体消失。
3. **浮层与全局**：8 个覆盖层各自手写 overlay / Esc / 焦点管理——Esc 会同关所有浮层、Tab trap 6/8 缺失、焦点还原 6/8 缺失，根因是**没有统一基座**，任何新弹窗都会继续漂移。

## 三、后端设计（R8–R12）

### R8 `run_tool` 写类工具角色护栏（P0）

问题：`routes/ai.py` 的 `/ai/chat*` 仅要求 viewer（`require_role("viewer")`），`_drive` 调 `run_tool(conn, name, args, actor=actor)` 不传角色，`suggest_lineage` / `draft_descriptions` 对 viewer 直接放行——同能力直通端点 `POST /ai/suggest`、`POST /ai/description-drafts/{id}/accept` 却要求 editor，`require_role` 门槛被对话路径整体绕过；抽屉头部还显示「只读工具」徽章。

方案（三层兜底，路由层为主）：

1. 路由层：`ai_chat` / `ai_chat_stream` 不改最低门槛（viewer 能问）；
2. **工具层强制**：`run_tool` 新增必传命名参数 `role`；`suggest_lineage` / `draft_descriptions` 落入 `WRITE_TOOLS` 集合，`ROLE_ORDER[role] < ROLE_ORDER["editor"]` 时抛 `ToolError("该工具需要 editor 角色权限；请在画布详情面板由 editor 执行血缘建议/描述草稿")`，作为工具错误回传模型（不中断整轮），`tool_trace` 记 `ok=false`——写库动作必须不发生；
3. `system prompt` 增补一句：viewer 对话时写类工具会被拒，提示用户改用 editor 账号或让 editor 在画布执行。

- `role` 取自 `require_role` 返回的 `user["role"]`（`security.py`）；`run_tool` 的 `role` **必传**，防止未来调用方漏传造成误放行；
- MCP server 只暴露 5 个只读工具，不受影响（07 §4.6 决策不变）；
- 前端「只读工具」徽章文案改为「查询即时可用；写提议需 editor 确认」（R17 一起落）。

### R9 SSE 心跳 + 客户端断开即停（P1）

问题：`event_stream` 在事件空档全静默，反向代理可能掐断；worker 为 daemon 线程，客户端断开后仍会跑完全部 LLM 调用与写工具（含 suggest 落库）——用户已离开，写动作照常发生。

方案（`routes/ai.py`）：

1. **心跳**：事件队列空转超过 15s 时 yield 注释帧 `: ping\n\n`（SSE 注释帧；前端 `api.ts` 解析器按帧找 `data: ` 行，空帧安全跳过，无需改前端）；
2. **断开即停**：新增 `cancelled = threading.Event()`；协程 `finally`（含 `GeneratorExit`）时置位并传入编排；`stream_run_chat` / `_drive` 每轮工具循环开头检查，置位即抛 `ChatInterrupted`（`ai/chat.py` 新异常类），worker 捕获后静默退出（不追加 error 事件——客户端已消失）；
3. 中断检查**在写工具执行之前**，保证取消后不再产生落库；
4. 非流式 `/ai/chat` 不变；顺带清理 `finally: pass` 残留。

### R10 上下文预算：工具结果截断 + 会话修剪（P0）

问题：工具结果 JSON 原样拼回对话（`get_field_details` 附 50 行回源预览、`trace_lineage` 可带全子图），前端回传历史 50 条 × 8000 字符，无任何预算控制——真实供应商下数轮即撑爆上下文窗口。

方案（`ai/chat.py`，对**所有**对话入口生效）：

1. **工具结果截断**：结果在抽取 `graph` / `highlights` / `suggestions` / `drafts`（画布联动不受截断影响）**之后**、以 `role=tool` 拼回对话**之前**，JSON 序列化超过 `MAX_TOOL_RESULT_CHARS = 4000` 字符即截断并附中文截断标记（`…[已截断，完整数据共 N 字符]`）；截断只影响模型可见文本；
2. **会话修剪**：新 `_estimate_tokens(text)`（ASCII ≈ 4 字符/token，CJK ≈ 1 字符/token）与常量 `CONTEXT_TOKEN_BUDGET = 96_000`（`.env` 可选 `LLM_CONTEXT_TOKEN_BUDGET` 覆盖，config.py 增加）；每轮把工具结果拼回后，若累计超预算，**从最旧的完整轮次块**（assistant + 其全部 tool 消息构成的最先可整块移除单元）开始整块删除，直到低于预算；system 与当前轮次永不删除；
3. 明确边界：本项只做「截断 + 修剪」第一步；目录摘要注入与历史摘要化属 07 演进项 10 的后续轮次，不在本轮。

### R11 AI 路由速率限制（P1，无新增依赖）

问题：`/ai/chat*`、`/ai/suggest` 无每用户限流，viewer/editor 可无限并发调用 LLM（成本失控）与启发式扫描。

方案（新 `src/clew/ai/ratelimit.py`）：

- `ai_limiter(window_seconds, max_requests)`：FastAPI 依赖工厂，内存滑动窗口（`time.monotonic` + 每用户名一个 deque + `threading.Lock`），超限抛 `HTTPException(429, detail=…)` 并带 `Retry-After` 头；
- 挂载：`/ai/chat`、`/ai/chat/stream` → 每用户 10 次/60s；`/ai/suggest*` → 6 次/60s；drafts accept/reject 属廉价写，不挂限流【TBD-OPS：阈值现按猜测定，可观察使用后调参】；
- 窗口按进程内存计，单机部署足够；多进程部署需外置存储，本产品单机形态不做（§五同步记录）。

### R12 描述草稿 prompt 语言参数化（P2 顺手）

问题：`_DRAFT_PROMPT` 固定「写一句中文描述」，英文对话产出的草稿也是中文。

方案：`descriptions.draft_descriptions(..., lang: str = "zh")` 增语言参数，prompt 双模板（zh/en）；`draft_descriptions` 工具 schema 增 `lang` 枚举 `["zh","en"]`（缺省 zh），由模型按对话语言填写；REST 直通端点不变。

### 新增测试（并入 `tests/test_review_fixes.py`，沿用 R 编号）

- R8：viewer 发消息触发 `suggest_lineage` → 断言候选未落库（edge 表无 `source='ai'` 行）+ `tool_trace` 该项 `ok=false`；editor 账号同输入 → 正常落库；
- R9：SSE 用例消费事件流，断言长静默轮中可见 `ping` 注释帧；客户端提前关闭后断言无进一步写库（monkeypatch LLM 慢速 + 线程 join 前查表）——如并行成本过高，退化为 `_drive` 的 `should_interrupt` 单测（round 间抛 `ChatInterrupted`）；
- R10：伪造超长工具结果 → 断言拼回消息 ≤ 上限且带截断标记；伪造超预算历史 → 断言最旧轮次被整块删掉且 system 保留；
- R11：同用户 11 连发 `/ai/chat`（LLM 未配置场景，请求即被 503 前的限流依赖拦截——顺序注意：限流依赖在 `require_role` 之后注册，断言 429）；
- R12：`lang="en"` → prompt 模板为英文版（对 `llm.complete` 的入参做断言）。

## 四、前端设计（R13–R18）

### R13 浮层基座：`useOverlayBehavior` + `ModalShell`（P0，根因收口）

现状：8 个覆盖层（ConfirmDialog / EdgeCreateModal / ImportWizardModal / PreviewModal / UserManagementModal / VersionDrawer / HistoryDrawer / AiAssistantDrawer）各写各的：Esc 各自挂 document 且互不知层级（一次 Esc 全关）、Tab trap 仅 2/8、焦点还原 6/8 缺失、body 滚动锁 7/8（ImportWizard 不锁）。结论是约定互斥不是机制互斥。

方案：

1. 新 hook `lib/useOverlayBehavior.ts`：打开时保存 `document.activeElement`、挂 Esc（**只有一个浮层响应 Esc**——见第 2 条）、Tab 循环 trap、卸载/关闭时还原焦点、锁定 `body.style.overflow`；`onRequestClose` 回调统一走 `requestClose`（busy 态可拒关）；
2. **Esc 栈**：模块级 `overlayStack`（useEffect 时入栈/出栈），栈顶才响应 Esc——两抽屉同开只关最近一层；
3. 新组件 `components/ModalShell.tsx`：覆盖 overlay（`fixed inset-0`）+ 卡片容器（居中弹窗 / 右侧抽屉两种变体）+ 统一 header（图标徽章 + 标题 + 关闭钮）+ footer 插槽；8 个覆盖层迁入，样式类沿用各自现有 Tailwind 类，仅结构替换（视觉零变化目标）；
4. Workspace 侧所有 `onClose` 内联函数改 `useCallback`（R18 之外的稳定性前置，R13 一并落——抽屉 effect 不得因父渲染重挂抢焦点）；
5. 交付时逐浮层列出迁移清单（文件 ⇒ Shell 变体），供验证核对。

### R14 TopBar 响应式收敛（P0）

现状：头部 `h-14 flex` 固定高度、全部操作无条件渲染，768–1279px 合计宽度超屏、末尾被裁切（仅品牌文案与用户名做了响应式隐藏）。

方案：`lg`（1024px）以下「导入 / AI 助手 / 版本」降为 icon-only（保留 `aria-label` + `title`）；`md`（768px）以下：hops 组由 5 个按钮收为 1 个下拉（`select`），语言切换并入用户菜单；头部加 `min-w-0`，溢出安全降级。焦点样式与原有一致（`focus-visible:ring`）。

### R15 画布修复（P1）

1. **dagre 布局 memo 化**：把 `LineageCanvas` 巨型 effect（450–898 行）拆两层——`graph + collapsedGroupIds + expandedDatasetIds` 变化时才重跑 `layoutDatasets`（`useMemo`），「追踪态染色」依赖 `chain` 只做浅更新（节点 data 引用不变的字段跳过重建）；
2. **空态闪现**：`datasetsLoading` 传入画布，首屏显示加载卡而非「请选择数据集」；
3. **过滤空态提示**：过滤后边数为 0 且原图边数 > 0 时，画布顶部 Panel 显示「当前过滤器下没有可见连线」i18n 提示；
4. **移动端提示**：底部提示条改为 `md` 以下首次进入可关闭浮层（`localStorage` 记忆，文案含「框选 ≥2 个节点可折叠为组」）；
5. **Controls 内置英文 aria-label** 透传本地化文本；hops 按钮组改 `role="radiogroup"` + `aria-checked`。

### R16 边操作键盘可达（P0，次入口方案）

问题：`edgesFocusable=false` + 工具条 hover 驱动，键盘用户无法查看/编辑/删除边（`EdgeDetailPanel` 唯一入口是 hover 工具条）。

方案：画布底部新增浮动「边列表」Panel（与图例同侧、可折叠）：默认显示当前过滤图的前 20 条边（从 `filteredGraph.edges` 读，含方向与来源徽章），每行均为可聚焦按钮，Enter 选中 → 走既有 `onEdgeSelect` 链路打开 `EdgeDetailPanel`；搜索框支持筛选。选中字段时列表优先显示该字段的上下游边并高亮。此方案不依赖 React Flow 边聚焦（避免重画边交互），hover 工具条保持不变。

### R17 AI 抽屉 UX（P1）

1. **停止按钮**：`sending` 态发送键变「停止」，点击即 `abortRef.current.abort()`；现有 abort 逻辑保留；
2. **关闭即软中断**：抽屉 `onClose` 先 abort 进行中的流再收起（流已在进行时向用户明确提示「已停止」，不静默）；
3. **清空会话**：头部新增「清空对话」按钮（`ConfirmDialog` 确认，清 `entries` 与后续上下文），会话历史仍存内存（持久化延后，§六）；
4. **内联候选确认卡**：`suggest` 事件到达即在本轮回答气泡下方渲染候选清单卡（复用 `/ai/suggest/confirm|reject` 接口与 DetailPanel 既有候选卡状态/文案），卡片带「在画布中查看」按钮（跳转到种子字段）——viewer 收到的卡片置灰并提示需 editor（与 R8 对齐）；
5. **徽章文案**：「只读工具」→「查询实时可用；建议/草稿等写操作需 editor」（zh/en 各自改 ai dict）。

### R18 Toast 升级与杂项打包（P1）

1. **Toast**：去掉容器 `pointer-events-none`；错误级（`variant=error`）停留 ≥8s 且有关闭钮，操作按钮插槽（重试）；同时把「仅 toast 的错误」（回滚失败等）在所属抽屉保留 `role=alert` 副本（VersionDrawer 已有 rollbackNotice 区可复用）；
2. **稳定 onClose**：`Workspace` 全部浮层开关改 `useCallback`（R13 同步完成后兜底）；
3. 杂项：
   - `UserManagementModal` 用户列表角色徽章改走 `roleLabel(user.role, t)`（`lib/roles.ts` 现成）；
   - `lib/api.ts`：删除死代码 `sendAiChat`（无调用方）；错误详情拼接的中文分号『；』改为按 locale 取分隔符；
   - `LoginPage`：分字段空值校验（「请输入用户名」/「请输入密码」分引）；
   - `ImportWizardModal`：步②切换格式若会丢弃已选文件，弹 `ConfirmDialog` 二次确认；
   - `PreviewModal`：「复制定位器」按钮小屏移入 footer（去 `hidden sm:flex`）；
   - `HistoryDrawer`：条目达 50 条上限时显示「仅显示最近 50 条」提示；
   - `VersionDrawer`：三个写操作（建标签 / diff / 回滚）接入 `AbortController`，卸载即断。
