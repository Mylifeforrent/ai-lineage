# 06 · AI 回答的画布联动高亮（修复文档）

> 状态：已实现并验证（prototype 先行验证 → 同步正式 `backend/` 与 `frontend/`）。日期：2026-10-24。
> 关联：[02_前端开发文档](./02_前端开发文档.md) §7.3「字段追踪链路」、§7.6「AI 出图联动」；[05_API接口文档](./05_API接口文档.md) §13.2；[03_后端开发文档](./03_后端开发文档.md) §8.2/§8.4。

## 一、问题

用户在 AI 助手抽屉提问：

> 「订单里面的 amount 字段上下游都对应哪些表，把对应的结果给我高亮显示。」

AI 正确调用了工具、返回了子图（画布切换到对应范围），并在回答正文里写了「高亮结果」——但**画布上没有任何高亮**。

同时，AI 助手抽屉的空态文案早已承诺「返回子图时画布会自动切换并高亮」，其中「高亮」从未实现。

## 二、根因

1. **后端契约没有高亮通道**：`POST /ai/chat` 只返回 `{answer, tool_trace, graph?}`（`ai/chat.py` 的 `run_chat`）。`trace_lineage` 工具虽然知道查询的字段，但该信息在组装响应时被丢弃，前端无从得知「这轮回答聚焦哪些字段」。
2. **工具集没有高亮声明手段**：模型只能调 4 个查询类工具，无法向前端传达「把哪些字段标出来」的意图，只能把它写进 markdown 正文（前端不解析正文）。
3. **前端没有消费点**：`Workspace.handleAiGraph` 只做 `setAiGraph + applyGraph`（画布切换子图）；`LineageCanvas` 的字段追踪高亮（`focusFields`）只能由点击字段行触发，AI 链路完全没有接入。

## 三、修复方案

### 3.1 后端：新增 `mark_highlight` 工具 + `highlights` 响应字段

**新工具 `mark_highlight`**（`ai/tools.py`，只读、不返回业务数据）：

- 参数：`{ fields: [{dataset, field}, …] }`，最多 `MAX_HIGHLIGHT_FIELDS = 8` 个；
- 行为：逐项校验字段存在性（SELECT），去重；不存在的项记入 `ignored` 回传模型；**全部不存在**时抛 `ToolError` 让模型自我纠正（对话不中断）；
- 定位：画布联动信号——模型用它「声明」本次回答聚焦、需要在前端画布上以红色追踪链高亮的字段。

**system 提示**（`ai/chat.py`）新增：工具列表加入 `mark_highlight`，并增加回答规则第 4 条——用户要求「高亮/标记/标出」结果，或回答围绕某些字段的上下游时，**在给出最终回答前调用 `mark_highlight`**。

**响应契约**：`run_chat` 汇总本轮所有 `mark_highlight` 调用（跨调用去重，上限 8），非空时返回：

```json
{
  "answer": "…",
  "tool_trace": [ { "tool": "mark_highlight", "args": {…}, "ok": true }, … ],
  "graph": { … },
  "highlights": [ { "dataset": "d0", "field": "amount" }, … ]
}
```

`highlights` 为**可选键**——模型未调用该工具时不下发，旧前端忽略即可，向后兼容。

### 3.2 前端：AI 声明 → 画布追踪链

沿用已有的字段追踪高亮实现（[02_前端开发文档](./02_前端开发文档.md) §7.3），把触发源从「点击字段行」扩展到「AI 声明」：

| 环节 | 改动 |
|---|---|
| `lib/fieldChain.ts` | `computeFieldChain` 的 focus 参数从单字段改为**字段数组**（多起点无向 BFS），起点 role='focus'、沿途 role='linked' |
| `types.ts` | 新增 `AiHighlightItem {dataset, field}`；`AiChatResponse` 增加可选 `highlights` |
| `AiAssistantDrawer` | `onGraph` 签名扩展为 `(graph: LineageGraph \| null, highlights?: AiHighlightItem[])`；响应带 `graph` 或 `highlights` 即回调；工具轨迹标签表加 `mark_highlight: '标记高亮'` |
| `Workspace` | 新增 `aiFieldFocus` 状态 `{seq, fields}[]`（seq 区分每一轮回答）；`handleAiGraph` 每轮回答都更新它——有 `highlights` 应用、没有则显式清空；数据集/跳数切换与刷新时置空；透传给画布 |
| `LineageCanvas` | 焦点状态 `focusedField(单)` → `focusFields(数组)`；新增 `aiFocusFields` prop，effect 按 seq 校验字段存在 → 复用 `revealChainFields` 自动展开链路涉及的折叠表/字段列表 → 应用为追踪焦点；`DatasetNode` 数据改为 `focusedFieldNames[]` |

**应用效果**：与点击字段完全一致——命中链路的边变红（`#DC2626`）加粗流动，其余连线压暗 opacity 0.15；聚焦字段行强红、链路字段行浅红、handle 红色。

**清除/覆盖时机**（与点击追踪一致，另加两条 AI 特有规则）：

- 点击画布空白（`onPaneClick`）、点击连线、框选节点、切换种子/跳数、子图刷新后焦点字段失效——同点击路径；
- **新一轮 AI 回答未声明 `highlights`** → 显式清除上一轮追踪态（seq 递增保证每轮回答都被画布感知，不会残留旧高亮）；
- AI 声明的字段不在当前子图（如模型标注了子图外字段）→ 逐项校验后跳过，全部无效则不高亮、不压暗。

## 六、已知边界

- `highlights` 依赖模型遵循 system 提示在回答前调用 `mark_highlight`；模型不调用时该轮回退为「只切图不高亮」（与修复前行为一致），不会报错。
- 高亮沿「库内字段级边 + 同名字段匹配推断线」传递（§7.3 口径）；若链路两端只有表级边且无同名字段，则该段不会出现在红色链路中。
